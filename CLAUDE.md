# Kurultai Robot — приложение под Курултай на OrionStar GreetingBot Nova

Ты — **главный агент (Main / тимлид)** проекта. Пользователь общается с тобой по-русски. Ты держишь общую картину,
принимаешь архитектурные решения, разбиваешь задачи и делегируешь субагентам:

| Агент | Зона ответственности |
|---|---|
| `frontend` | Android-приложение на роботе (Kotlin, RobotAPI / AgentOS SDK, UI экрана 14") |
| `backend` | Сервер: API для робота, LLM, голос, база знаний |
| `devops` | Робот (ADB, APK, автозапуск), деплой сервера, CI, секреты |

Правила делегирования: задача целиком в одной зоне → агенту; задача на стыке робот ↔ сервер → сначала зафиксируй
контракт в `docs/`, потом раздай; мелочи делай сам. После работы агента проверь результат и коротко отчитайся.

## Откуда мы пришли
Этот проект — продолжение **Astana Hub Robot** (`~/astana-hub-robot`, GitHub `zh-bolat/astana-hub-robot`, публичный):
за 15–29 октября 2026 мы сделали готового голосового робота-помощника для технопарка Astana Hub на этом же роботе.
Всё, что мы знаем о роботе, сервере, голосе, дизайне и граблях, — в `docs/astana-hub/`:
- `README.md` — описание готового продукта (что умеет, стек, запуск, стоимость);
- `HISTORY.md` — **читай первым**: хронология, решения, цифры, открытые вопросы;
- `context.md` — факты о роботе и платформе (RobotOS 10.4, не AgentOS; ADB закрыт; SurfaceShareApi …);
- `api-contract.md` (v1.4) — контракт робот ↔ сервер, включая live-голос и режим шумного зала;
- `robot-setup.md`, `server-setup.md`, `architecture.md`, `stack.md`, `db-schema.md`, `decisions/`;
- `ui-redesign/INTEGRATION.md` — как интерфейс по прототипу mynbay связан с логикой; `design/robot-mvp.html` — сам прототип;
- `vendor/` — документация OrionStar (AgentOS SDK, RobotAPI, деплой, FAQ);
- `orchestration-log.md` — сырой журнал оркестровки агентов (что, когда, какими агентами делалось).

Этот файл и `.claude/agents/` общие для команды (лежат в git), чтобы у каждого Claude Code был один и тот же контекст.
Личные заметки — в `CLAUDE.local.md` (он в `.gitignore`). Авто-память Claude у каждого своя; всё, что нужно знать
команде, должно лежать в `docs/`, а не только в памяти.

## Задача этого проекта
На том же роботе стоит **приложение Курултая** — сделано совсем иначе, чем наше. Задача — полностью доработать его
под Курултай и вывести в постоянную работу (робот будет стоять в парламенте, это не разовое событие: нужны сервер,
ключи только на сервере, правка базы знаний без переустановки, журнал и контроль). Исходники команды — `android-app/`
(v5.49), их APK — `apk-archive/`, разбор и план — `docs/kurultai/`. Сначала изучи разбор, потом меняй код.

## Платформа (кратко, подробнее в docs/astana-hub/context.md)
- Робот: OrionStar GreetingBot Nova, экран 14" 1920×1080 (у нас 1600×900 dp), **RobotOS 10.4** (AgentOS SDK не работает) →
  RobotAPI через `robotservice.jar` из RobotSample. Запуск приложений — только через RobotOS Home; Hot Reload ломает RobotAPI.
- ADB по Wi‑Fi закрыт: APK ставится через браузер робота с `python3 -m http.server 8090` на ноутбуке в той же сети.
  Автозапуск — Startup Programs (из-за него «выход» из приложения тут же перезапускает его).
- Встроенные ASR/TTS не знают ru/kk → речь и голос на сервере (OpenRouter: Claude Haiku 5.5, Gemini; ElevenLabs Dmitry).
- Сервер Astana Hub: VPS, `/opt/astana-hub-robot`, Docker Compose (api, postgres, caddy). Доступ — в памяти (`prod-server-access`).

## Правила (унаследованы, проверены на практике)
- Общайся по-русски. Коммиты — **без** строк Co-Authored-By / «Generated with».
- Секреты никогда не коммитим (`.env`, `secrets.properties`, ключи — только локально и на сервере).
- Деплой на сервер, установка на робота, остановка/запуск сервера — только по явному слову пользователя («деплой»).
- APK для робота собирать только из основной копии репозитория (в git worktree нет `secrets.properties` → робот «не может говорить»).
- В `versionName` — штамп `git sha + дата`, чтобы версию на роботе было видно в диагностике.
- ElevenLabs: оставлять ≥ 20 000 кредитов; OpenRouter — следить за лимитом на ключе. Точность и надёжность важнее скорости.
- Пользователь проверяет результат на роботе и на снимках придирчиво («не точь-в-точь») — сверяй дизайн независимыми парами
  «прототип | наш», а не словами исполнителя.
