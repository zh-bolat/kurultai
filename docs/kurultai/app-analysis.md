# Разбор присланного приложения Курултая («AI-помощник Комитета», v5.49)

Дата разбора: 2026-10-29. Исходники пришли архивом `курылтай.zip`; в архиве был пустой git команды
(один коммит «first commit» с README, remote `github.com/sungggat/kurultai-bot` — на GitHub не виден),
папка `DeputyAssistant/` с приложением и 110 APK всех версий (v1.0 → v5.49). Автор — Sunggat.

Куда положили:
- `android-app/` — бывший `DeputyAssistant/` (приложение + скрипты + README автора);
- `backend/` — бывший `DeputyAssistant/server/` (необязательный Node-шлюз к OpenAI);
- `apk-archive/` — все 110 APK (в git не попадают, `*.apk` в `.gitignore`);
- оригинальная загрузка целиком сохранена в `~/kurultai-original-upload/` (вне репозитория).

## Что это

Пакет `kz.kurultai.assistant`, название «AI-помощник Комитета». Персона: «ИИ-помощник депутата
Ахмедиева Дархана Мейрамулы, председателя Комитета по цифровизации, инновациям и науке» (зашито в
системный промпт и в приветствие). Языки — русский и казахский, переключатель в шапке.

| Слой | Как сделано |
|---|---|
| Язык | Java (без Kotlin, без AndroidX, без Compose); 5 классов, 2 259 строк |
| Сборка | Gradle 8.9, AGP 8.7.3, compileSdk 34, targetSdk 29, minSdk 23; `versionName 5.49.0-ai-assistant-identity`, подпись debug-ключом |
| Зависимости | `libs/robotservice.jar` (RobotAPI; **тот же файл, что у нас в Astana Hub**, md5 совпадает) + Gson 2.10.1 |
| UI | один `WebView` на весь экран → `file:///android_asset/index.html`; все экраны в `app.js` (48 КБ в 135 строках), стили в `styles.css` (32 КБ), SVG-карта Казахстана на 20 регионов |
| Мост | `RobotBridge` (`@JavascriptInterface`, в JS объект `Robot`) ↔ коллбеки `window.on*` (≈35 штук) |
| LLM | OpenAI Responses API **напрямую с робота**, модель `gpt-5.6-luna` (в README/сервере — `gpt-6-astra`), `web_search` с allowlist официальных доменов (gov.kz, parlam.kz, quryltai.kz …) |
| ASR | запись WAV на роботе (`WavRecorder`: 16 кГц стерео → моно, левый канал, AEC) → OpenAI `audio/transcriptions` (`gpt-4o-transcribe`) |
| TTS | `SkillApi.playText` робота (RobotOS), резерв — Android `TextToSpeech` |
| Данные Курултая | `QuryltaiDataSync`: раз в сутки 4 публичных API `quryltai.kz` (законопроекты, планы работы, комитеты с депутатами, депутатские запросы) → кэш в SharedPreferences → **весь снимок вклеивается в prompt** каждого запроса |
| Ключ OpenAI | хранится на роботе (Android Keystore, AES-GCM). Ввод: поле в ⚙, «вставить из буфера», или `adb shell am start … --es openai_api_key` (`provision_openai_key.command`). В исходниках, `BuildConfig` и APK v5.49 ключа нет |
| Сервер | `backend/server.mjs` — 116 строк Node, `POST /assistant` → OpenAI; в UI спрятан в «Дополнительно: собственный шлюз». По умолчанию не используется |

## Экраны (по `index.html` / `app.js`)

1. **Главная** — hero с «орбом», поле вопроса + микрофон, 4 быстрые кнопки (законопроект, заключение комитета,
   цифровые обращения, AI- и киберриски), блок «Сегодня» (первая строка подменяется недельным планом с quryltai.kz).
2. **Аналитика** — 5 вкладок дашбордов (цифровизация, инновации, наука, кибербезопасность, законотворчество),
   интерактивная карта регионов, тренд, «сигналы». **Все цифры — демо, захардкожены** (есть метка «ДЕМО-ДАННЫЕ»).
3. **Законопроекты** и **Заседание** — списки из кэша quryltai.kz (реальные данные).
4. **Обращения** и **Поручения** — захардкоженные демо-строки.
5. **Ответ** — заголовок, текст ответа, «Озвучить», кнопки «Создать выступление / Сформировать поручение / Экспорт».
6. **Робот** — батарея/зарядка/карта/точки, ручное движение (с «разблокировать»), голова, навигация к точке, на зарядку.
7. **Настройки (модалка)** — ключ OpenAI, режим микрофона (ручной / авто), язык ответа (авто / ru / kk),
   ближайшая встреча (локальное напоминание за час), адрес своего шлюза.
8. **Голосовой док** внизу — кнопка «удерживайте и говорите», статус, транскрипт.

## Как проходит голосовой ход

```
лицо в кадре (PersonApi.getCompleteFaceList, опрос 1 с, ≤ 2.2 м)
  → поворот головы/корпуса, приветствие голосом робота
  → [авто-режим] запись с VAD по уровню (порог 3, при речи робота 12; тишина 1.2 с; максимум 10 с)
     [ручной режим] hold-to-talk
  → WAV → OpenAI transcriptions (HTTPS с робота)
  → фильтр: «иди за мной / стой» → BodyFollow; иначе shouldAnswerSpeech() по словарю вопросов/тем
  → OpenAI Responses (инструкции + снимок quryltai.kz + при вопросе о планах ещё PDF недельного плана как input_file)
  → чистка текста → SkillApi.playText (робот) → fallback Android TTS
  → barge-in: через 0.65 с после начала речи снова слушает, громкий голос прерывает TTS
```

Контекст диалога — только один предыдущий обмен и только если эвристика `isContextualFollowUp` решила,
что это уточнение.

## Что в этом хорошо (стоит взять)

- **Присутствие и приветствие**: только по лицу (не по звуку/телу), ближайший ≤ 2.2 м, защита от повторного
  приветствия (12 с / тот же человек 3 мин), поворот головы и корпуса к посетителю, «посетитель отошёл».
  У нас в Astana Hub такого слоя не было.
- **Follow-режим** («иди за мной» / «стой»): `startBodyFollowAction` по id полного лица, повтор при ошибке −117,
  расшифровка статусов 1008/1013/1023/1028/1032. Проверено на том же роботе.
- **Синк quryltai.kz**: известны 4 рабочих публичных API и их поля (`draft-laws`, `work-plans/plans`,
  `committees/with-deputies`, `deputy-requests`). Это готовый источник базы знаний для нашего сервера.
- Промпт-правила для официальных данных (только первичные источники, без URL в речи, «Республика Казахстан»
  полностью, лимит 70 слов, маркер `[REPEAT]` на бессвязный ввод) — хорошая основа для нашего промпта.
- Робот-страница (движение, голова, навигация, зарядка) — рабочие вызовы RobotAPI.
- `Speaker`: чистка markdown/ссылок перед озвучкой, нарезка на куски, «не обрывать на половине мысли».

## Что плохо / риски

1. **Архитектура**: один `MainActivity` на 1,5 тыс. строк и один `app.js` в 135 строк по 300–2 000 символов.
   Нет сборки фронта, нет тестов, нет заглушек для эмулятора. Любая правка UI — редактирование минифицированного кода руками.
2. **Ключ OpenAI на роботе** + `usesCleartextTraffic=true`. Ключ вводится через буфер обмена или USB.
   Наш принцип (ключи только на сервере) здесь нарушен.
3. **Задержка**: два последовательных HTTPS-вызова OpenAI с робота (транскрипция, потом ответ с web_search),
   без стриминга. Ожидаемо заметно медленнее нашего live-режима (`WS /v1/live`).
4. **ASR в зале**: VAD по громкости с порогом 3 из 100 — в шумном холле будут ложные срабатывания;
   транскрипция без стриминга и без подсказки языка. У нас режим шумного зала уже решён в контракте v1.4.
5. **TTS робота для ru/kk**: автор надеется, что «движок сам выберет русский/казахский по тексту». Наш опыт на
   этом же роботе: встроенный TTS ru/kk не умеет, поэтому мы ушли на ElevenLabs. Надо проверить APK на роботе,
   но скорее всего казахский там читается плохо или не читается.
6. **Данные**: аналитика, обращения, поручения — демо. Реальные только законопроекты, планы, составы комитетов,
   депутатские запросы (quryltai.kz). Весь снимок (все комитеты, 100 запросов) вклеивается в каждый prompt.
7. **Модель**: в коде `gpt-5.6-luna`, в README и сервере `gpt-6-astra`; `reasoning: none`, `max_output_tokens 600`.
8. **Релиз**: подпись debug-ключом, `versionName` без sha/даты, установка через `adb` по USB (у нашего робота ADB
   по Wi‑Fi закрыт; USB-отладку автор включал — проверить на нашем экземпляре).
9. Привязка к одному депутату и одному комитету зашита в промпт, приветствие и UI; для «робота Курултая» в целом
   это придётся параметризовать.

## Сравнение с нашим Astana Hub

| | Курултай (присланное) | Astana Hub (наше) |
|---|---|---|
| Оболочка | Java + WebView, 1 Activity | Kotlin, XML Views, MVVM, flavors emulator/robot |
| LLM | OpenAI напрямую с робота, ключ на роботе | сервер FastAPI, OpenRouter (Claude Haiku 5.5 / Gemini), ключи на сервере |
| ASR / TTS | OpenAI transcribe / TTS робота | сервер: STT + ElevenLabs Dmitry (ru/kk/en), live-режим по WebSocket |
| База знаний | снимок quryltai.kz в prompt | Postgres + Google-таблица, `/v1/ask`, источники |
| Присутствие | лицо → приветствие, follow | нет |
| Дизайн | свой, «комитетский дашборд» | прототип mynbay v9, сверен попиксельно |
| RobotAPI | тот же `robotservice.jar` | тот же |

## Чего не хватает, чтобы планировать точно

- **ТЗ**: `docs/kurultai/TZ.md` пока нет. Нужно: где стоит робот на Курултае (холл, зал, кабинет), кто
  пользователь (посетители / депутаты / аппарат), какие сценарии обязательны.
- Нужен ли режим «помощник конкретного депутата» или «робот Курултая» для всех.
- Чей аккаунт OpenAI использовался и есть ли требование остаться на OpenAI (у нас OpenRouter + ElevenLabs).
- Какие экраны реально нужны: аналитика и карта сейчас декоративные.
- Дизайн: перерисовываем под прототип mynbay или оставляем их стиль.

## Предложение: над чем работать

Рекомендация — **не дорабатывать WebView-код, а перенести продукт на нашу архитектуру**, забрав из присланного
всё ценное. Иначе каждая правка UI и каждая проблема с задержкой/шумом будет решаться заново в минифицированном JS.

1. **Сервер (backend)**. Эндпоинт для Курултая на нашем VPS по контракту v1.4: синк quryltai.kz переезжает с робота
   на сервер (те же 4 API), снимок кладётся в базу знаний, промпт помощника берём за основу их инструкций.
   Live-голос, STT/TTS (ElevenLabs), режим шумного зала — уже есть.
2. **Робот (frontend)**. Новая Kotlin-оболочка на базе Astana Hub: наш `RobotGateway`/`VoiceGateway` + перенос
   их слоя присутствия (лицо → приветствие → поворот → follow) и робот-страницы. Прямые вызовы OpenAI и Keystore убираем.
3. **UI**. С mynbay решаем набор экранов: Главная, Ответ/чат, Законопроекты, План недели, Комитеты и депутаты,
   Депутатские запросы; демо-аналитику либо убираем, либо наполняем реальными цифрами (stat.gov.kz).
4. **Devops**. `versionName = sha + дата`, release-подпись, установка через браузер робота (как у нас), один
   `.env` на сервере, никаких ключей на устройстве.
5. **Проверка на роботе**. Поставить их v5.49 из `apk-archive/` и посмотреть вживую: как звучит казахский TTS,
   как ведёт себя приветствие и follow — чтобы знать, что именно переносим.

Альтернатива (если сроки горят): оставить WebView, заменить только транспорт (их `askBackend` уже умеет ходить
в произвольный `/assistant`) на наш сервер и перевести TTS на ElevenLabs. Быстро, но архитектурные проблемы 1–4 остаются.
